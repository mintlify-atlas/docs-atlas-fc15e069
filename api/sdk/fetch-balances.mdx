---
title: "fetchBalances() — Query BTC Balances Across All Layers"
sidebarTitle: "fetchBalances()"
description: "Fetch native and BTC-pegged asset balances across all five Peel layers in parallel. Returns a unified BalanceMap with per-layer breakdown and totalBtcSats."
---

`fetchBalances` queries all five Peel-supported layers in parallel and returns a
unified `BalanceMap`. A single failing RPC does not prevent the others from
returning — failed entries carry an `error` field and contribute `0n` to the
running total. The function is the foundation of the routing engine: it is called
internally by `routePayment` to determine which chains hold enough balance to
source the payment.

```typescript
import { fetchBalances } from "@peelbtc/sdk";
import { buildBridIdentityMap } from "@peelbtc/core";

const identity = buildBridIdentityMap(address, message, sigBase64);
const result = await fetchBalances(identity);

console.log("Total BTC (sats):", result.totalBtcSats.toString());
for (const entry of result.layers) {
  console.log(`${entry.layer} ${entry.asset}: ${entry.balance}`);
}
```

---

## Function signature

```typescript
async function fetchBalances(
  identity: BridIdentityMap,
  overrides?: RpcOverrides,
): Promise<BalanceMap>
```

---

## Parameters

<ParamField body="identity" type="BridIdentityMap" required>
  The sender's BRID identity map, produced by `buildBridIdentityMap()` in
  `@peelbtc/core`. Contains derived addresses for each supported layer. The
  function reads the following addresses from `identity.derived`:

  - `"bitcoin"` — Bitcoin address (UTXO query via mempool.space)
  - `"stacks"` — Stacks address (STX + sBTC via Hiro API)
  - `"bob"` — EVM address shared across BOB, Rootstock, and Citrea

  The `identity.root` field determines mainnet vs. testnet: addresses starting
  with `tb1` are treated as testnet.
</ParamField>

<ParamField body="overrides" type="RpcOverrides">
  Optional per-layer RPC or API URL overrides. Falls back to the public
  endpoints in the `@peelbtc/core` NETWORKS registry when omitted.

  ```typescript
  interface RpcOverrides {
    bitcoin?: string;    // e.g. "https://mempool.space/api"
    stacks?: string;     // e.g. "https://api.hiro.so"
    bob?: string;        // e.g. "https://rpc.gobob.xyz"
    rootstock?: string;  // e.g. "https://public-node.rsk.co"
    citrea?: string;     // e.g. "https://rpc.mainnet.citrea.xyz"
  }
  ```

  <Note>
    Provide your own RPC URLs in production. The public default endpoints are
    subject to rate limits.
  </Note>
</ParamField>

## Return type

### `BalanceMap`

<ResponseField name="layers" type="LayerBalance[]">
  One entry per asset per layer. A layer with both a native asset and a token
  (e.g. BOB: ETH + wBTC) produces two entries. Failed fetches produce a single
  error entry with `balance: 0n`.

  <Expandable title="LayerBalance fields">
    <ResponseField name="layer" type="string">
      The layer identifier: `"bitcoin"`, `"stacks"`, `"bob"`, `"rootstock"`, or
      `"citrea"`.
    </ResponseField>
    <ResponseField name="address" type="string">
      The address that was queried on this layer.
    </ResponseField>
    <ResponseField name="asset" type="string">
      Asset symbol: `"BTC"`, `"STX"`, `"sBTC"`, `"ETH"`, `"wBTC"`, `"RBTC"`,
      or `"cBTC"`.
    </ResponseField>
    <ResponseField name="kind" type='"native" | "token"'>
      Whether this is the chain's native asset or a token contract balance.
    </ResponseField>
    <ResponseField name="balance" type="bigint">
      Raw balance in the asset's smallest unit. Use `decimals` to convert.
      Bitcoin and sBTC: satoshis. STX: microSTX. ETH/RBTC/cBTC: wei.
    </ResponseField>
    <ResponseField name="decimals" type="number">
      Number of decimal places for this asset. See the asset table below.
    </ResponseField>
    <ResponseField name="isBtc" type="boolean">
      `true` if this asset is BTC-denominated and contributes to
      `totalBtcSats`. True for BTC, sBTC, wBTC, RBTC, and cBTC. False for STX
      and ETH.
    </ResponseField>
    <ResponseField name="testnet" type="boolean">
      Whether this balance was fetched from a testnet endpoint.
    </ResponseField>
    <ResponseField name="error" type="string | undefined">
      Set when the fetch for this asset failed. The `balance` will be `0n`. All
      other layers are unaffected — failures are isolated per asset.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="totalBtcSats" type="bigint">
  Total BTC held across all layers, in satoshis. Sum of all `LayerBalance`
  entries where `isBtc` is `true`, with EVM 18-decimal assets converted via
  `wei / 10^10`. Only includes successfully fetched balances — failed fetches
  contribute `0n`.
</ResponseField>

<ResponseField name="fetchedAt" type="number">
  Unix timestamp in milliseconds when the fetch was initiated.
</ResponseField>

## Asset reference

| Layer | Asset | Kind | Decimals | `isBtc` |
|---|---|---|---|---|
| Bitcoin | BTC | native | 8 | ✅ |
| Stacks | STX | native | 6 | ❌ |
| Stacks | sBTC | token | 8 | ✅ |
| BOB | ETH | native | 18 | ❌ |
| BOB | wBTC | token | 8 | ✅ |
| Rootstock | RBTC | native | 18 | ✅ |
| Citrea | cBTC | native | 18 | ✅ |

## Wei → satoshis conversion

EVM BTC-pegged assets (RBTC, cBTC, tBTC) are stored with 18 decimal places (wei).
`fetchBalances` converts them to satoshis before summing `totalBtcSats`:

```
1 BTC  = 10^8  satoshis
1 BTC  = 10^18 wei
1 sat  = 10^10 wei

sats = wei / 10^10
```

This integer division truncates sub-satoshi precision. The `balance` field for
these assets is stored in wei — divide by `10n ** 10n` yourself if you need the
satoshi equivalent per entry:

```typescript
const rbtcEntry = result.layers.find((l) => l.asset === "RBTC");
if (rbtcEntry) {
  const rbtcSats = rbtcEntry.balance / 10n ** 10n;
  console.log("RBTC in sats:", rbtcSats.toString());
}
```

## Code example

```typescript
import { fetchBalances } from "@peelbtc/sdk";
import { buildBridIdentityMap } from "@peelbtc/core";

// Build identity from a verified BRID signature
const identity = buildBridIdentityMap(address, message, sigBase64);

// Fetch balances with optional RPC overrides
const result = await fetchBalances(identity, {
  bitcoin: "https://mempool.space/api",
  stacks:  "https://api.hiro.so",
  bob:     "https://rpc.gobob.xyz",
  // rootstock and citrea default to public nodes
});

console.log("Fetched at:", new Date(result.fetchedAt).toISOString());
console.log("Total BTC (sats):", result.totalBtcSats.toString());

for (const entry of result.layers) {
  if (entry.error) {
    console.warn(`  ${entry.layer} ${entry.asset}: ERROR — ${entry.error}`);
  } else {
    const human = Number(entry.balance) / 10 ** entry.decimals;
    console.log(
      `  ${entry.layer} ${entry.asset}: ${entry.balance} (${human.toFixed(8)} ${entry.asset})`
    );
  }
}

// Check if the sender can afford a 100,000-sat payment on any chain
const canAfford = result.totalBtcSats >= 100_000n;
console.log("Can afford 100k sats:", canAfford);
```

<Tip>
  `fetchBalances` is called automatically by `routePayment` with the sender's
  identity. Call it directly when you need a balance snapshot outside of a
  routing context — for example, to display wallet balances in a UI.
</Tip>

## Behavior notes

- All five layers are fetched in parallel via `Promise.allSettled`. A single
  slow or failed RPC does not block the others.
- The Stacks layer returns **two** entries when both STX and sBTC are present.
- BOB may return **two** entries (ETH + wBTC) depending on whether the address
  holds any wBTC.
- If a layer address is missing from `identity.derived`, that layer is skipped
  (returns an empty result rather than an error).
- `testnet` is inferred from `identity.root`: `tb1…` addresses are testnet; all
  others are mainnet.
