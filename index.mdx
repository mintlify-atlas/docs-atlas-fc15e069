Peel is a Bitcoin payment routing SDK for Bitcoin L1 and its L2 ecosystem — Stacks, BOB, Rootstock, and Citrea. You describe what you want to pay (who, where, how much in sats), and Peel figures out which network, which bridge, and how to get there. You think in sats. The layers are invisible.

## What Peel Does

Bitcoin's L2 ecosystem fragments identity and BTC representations across every chain — different address formats, different token standards, different bridge protocols. Peel strips those layers away through three core ideas:

<CardGroup cols={3}>
  <Card title="Bitcoin Identity (BRID)" icon="key">
    All layer addresses derive from one secp256k1 public key. One Bitcoin key — every chain.
  </Card>
  <Card title="Balance Orchestration" icon="layer-group">
    Fetch BTC-denominated balances across all supported layers in a single `fetchBalances()` call.
  </Card>
  <Card title="Payment Routing" icon="arrows-split-up-and-left">
    `routePayment()` resolves the optimal route, checks liveness, selects bridges, and returns ordered execution steps.
  </Card>
</CardGroup>

## Get Started

<Steps>
  <Step title="Install the SDK">
    ```bash
    npm install @peelbtc/sdk@alpha
    ```
    `@peelbtc/core` and `@peelbtc/types` are installed automatically as dependencies.
  </Step>
  <Step title="Build a BRID identity">
    Sign the Identity Proof message with your Bitcoin wallet to create a cross-chain identity map.
    ```ts
    import { buildBridIdentityMap } from "@peelbtc/core";

    const identity = buildBridIdentityMap(address, message, sigBase64);
    // identity.derived → [bitcoin, stacks, bob, rootstock, citrea]
    ```
  </Step>
  <Step title="Route a payment">
    Pass the identity and destination to `routePayment()`. Peel handles the rest.
    ```ts
    import { routePayment } from "@peelbtc/sdk";

    const plan = await routePayment({
      from: identity,
      to: "SP2J6ZY48GV1EZ5V2V5RB9MP66SW86PYKKNRV9EJ7",
      amountSats: 100_000n,
    });

    // plan.steps[] — ordered execution steps
    // plan.intent  — resolved route, fees, timing
    ```
  </Step>
  <Step title="Execute the plan">
    Follow `plan.steps` in order. Each step is self-contained. Sign externally — Peel never holds keys.
  </Step>
</Steps>

## Supported Networks

| Network | Type | BTC Asset | Bridge |
|---|---|---|---|
| Bitcoin L1 | L1 | BTC | — |
| Stacks | L2 | sBTC | sBTC peg-in/out |
| BOB | L2 (OP Stack) | ETH + wBTC | BOB Gateway |
| Rootstock | L2 (EVM sidechain) | RBTC | Flyover peg-in |
| Citrea | L2 (ZK rollup) | cBTC | Direct transfer only |
